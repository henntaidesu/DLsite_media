# DLsiteMedia 页面加载与数据读取 性能优化任务书

> 范围：全部 WPF 页面（媒体库 / 标签 / 作品形式 / 收藏夹 / 搜索 / 下载 / 已下载 / 设置）+ 公共数据访问层（`Db` / `AppConfig`）+ 启动与导航（`App` / `MainWindow`）。
> 目标：消除 UI 线程阻塞、去掉重复的全表扫描与 N+1 查询、为大数据量媒体库引入真正的虚拟化，同时**不破坏既有约束**（参数化 SQL、下载/解压用裸线程、WAL 并发、DB 值不翻译）。

> **实施状态（2026-07-11 全部完成）**：A1 · A2 · A3 · B1 · B2 · B3 · B4 · C1 · C2 · C3 · C4 · C5 · D1 · D2 全部落地，`dotnet build` 通过、应用启动无异常。
> 关键改动：新增 `src/Controls/VirtualizingWrapPanel.cs`（均匀尺寸虚拟化换行网格，标准虚拟化+IScrollInfo）、`src/Services/ThumbnailCache.cs`（后台解码+LRU 缩略图缓存）；`AppConfig` 增版本戳 `Version`/`Invalidate()`，页面按版本戳条件 Reload；`MainWindow` 次级页惰性实例化；`MediaLibPage` 卡片区改虚拟化 `ItemsControl`、封面/正文/文件树全部异步读盘、文件树懒展开；`DownloadPage` 番号列表与子节点树虚拟化；`SearchPage` 社团网格换虚拟化面板、入库检查异步；`WebServer` 请求链路 async 到底。
> **注意**：虚拟化与异步 UI 改动较大，需在真实环境实跑回归（滚动、进入详情返回、文件树展开、多端并发访问 Web）。

## 二、优化任务清单

每个任务标注：**优先级**（P0 立即 / P1 近期 / P2 后续）、**涉及文件**、**方案**、**验收标准**。

### 阶段 A —— 公共层（收益最大、风险最低，先做）

#### 任务 A1 · 数据访问层去除每查询 PRAGMA 开销 【P0 · G1】
- **文件**：[src/Core/Db.cs](../src/Core/Db.cs)
- **现状**：`Open()` 每次新连接都跑 `PRAGMA journal_mode=WAL; synchronous=NORMAL`。WAL 是数据库级持久属性，建库时设一次即可；`synchronous` 可用连接串或建表时统一设置。
- **方案**：
  1. 将 WAL/synchronous 的设置**只保留在 `EnsureTables()` 里执行一次**，`Open()` 内删除 PRAGMA 块。
  2. `Open()` 内不再调用 `EnsureTables()`（改由 `App.OnStartup` 保证已初始化），去掉每查询的 `_initialized` 判断分支开销。
- **验收**：功能不变；用 SQL 探针确认查询路径不再发送 PRAGMA；并发下载 + UI 刷新无 `database is locked` 回归。

#### 任务 A2 · 为高频过滤列建索引 【P0 · G2】
- **文件**：[src/Core/Db.cs](../src/Core/Db.cs) `EnsureTables()`
- **方案**：在建表后补建（`CREATE INDEX IF NOT EXISTS`）：
  - `works(library)`、`works(state)`、`works(maker_name)`、`works(work_type)`、`works(down_time)`（列表排序用）
  - `work_genres(genre)`
  - `download_list(work_id)`、`download_list(status)`
- **验收**：媒体库/标签/形式页首屏查询、已下载页排序在万级 `works` 下明显加速；`EXPLAIN QUERY PLAN` 命中索引而非 `SCAN`。

#### 任务 A3 · 配置懒补齐 + 停止每次进页 Reload 【P1 · G3 / M3 / C1】
- **文件**：[src/Core/AppConfig.cs](../src/Core/AppConfig.cs)、各页 `IsVisibleChanged`
- **现状**：`Load()` 每次跑 ~40 条 `INSERT OR IGNORE`；页面每次可见都 `Reload()` 触发之。
- **方案**：
  1. `Load()` 的默认值补齐**仅在缺项时执行一次**：先 `SELECT` 现有 conf，只对缺失项做单批 `INSERT`（或首启动一次性补齐后置标志位）。
  2. 增加轻量 `AppConfig.Invalidate()`：仅标记缓存过期，下次读取才真正 `Load()`（惰性）。
  3. 页面 `IsVisibleChanged` 不再无条件 `Reload()`：改为订阅"配置已变更"信号（设置页保存时触发），或对比 `conf` 版本戳，未变则跳过。
- **验收**：连续切页不再产生批量 conf 写入（用 DB 写计数/日志验证）；设置页改动后其它页仍能读到新值。

### 阶段 B —— 媒体库家族（4 个 `MediaLibPage` 实例，视觉最重）

#### 任务 B1 · 卡片区真正虚拟化 【P0 · M1】
- **文件**：[src/Views/MediaLibPage.xaml](../src/Views/MediaLibPage.xaml)（`CardsScroll`/`ContentHost`）、[MediaLibPage.xaml.cs:67,856-910](../src/Views/MediaLibPage.xaml.cs#L67)
- **现状**：`WrapPanel` + 手动 `LoadMoreCards` 分批，元素只增不减；滚动过万级作品会累积上万个 `Border`。
- **方案**：把卡片区从"手工构建的 `WrapPanel`"改为数据驱动的虚拟化容器：
  - `ListBox`/`ItemsControl` + `ItemsPanel = VirtualizingStackPanel`（`VirtualizationMode=Recycling`）或 `VirtualizingWrapPanel`（自定义/引入），`ScrollUnit=Pixel`；
  - `ItemsSource` 绑定 `GridCard` 视图模型集合，`DataTemplate` 负责卡片外观（替代 `Func<Border> Build`）。
  - 保留现有"每层级卡片列表 + 搜索过滤键"的数据结构，仅替换渲染层。
- **验收**：万级作品滚动内存平稳（不随滚动线性增长）；滚动帧率顺滑；搜索/返回后滚动位置正确。
- **注意**：这是本任务书**改动量最大**的一项；建议单独分支，先在媒体库根视图落地，再推广到标签/形式/收藏夹（同一个类，天然复用）。

#### 任务 B2 · 封面/图片异步解码 + 缩略图缓存 【P0 · M2】
- **文件**：MediaLibPage 图片构建处（987-994 / 1215-1220 / 1490-1496 / 1841-1846）
- **方案**：
  1. 解码放到后台：用 `Task.Run` 在工作线程 `BitmapImage`（`OnLoad`+`DecodePixelWidth`）解码后 `Freeze()`，再回 UI 线程赋值；先显示占位/骨架。
  2. 进程级 `path|size|mtime → 弱引用/LRU` 缩略图缓存，避免详情↔返回重复解码（复用 `AudioPlayerBar` 增益缓存的键式思路）。
  3. `File.Exists(cover)` 的逐卡检查合并进后台解码流程，避免 UI 线程逐卡磁盘 stat。
- **验收**：批量卡片进入视口时 UI 不再卡顿；同一封面二次显示不再读盘解码。

#### 任务 B3 · 搜索/筛选防抖 + 查询异步化 【P1 · M4】
- **文件**：MediaLibPage `SearchBox_TextChanged`(766) / `ShowScopedSearch`(801-843)
- **方案**：搜索框加 250–300ms 防抖（`DispatcherTimer` 或 `CancellationToken` 取消上一次）；作用域 DB 查询走 `await Task.Run`，只有最后一次输入真正打库。
- **验收**：连续输入期间不产生逐字查询；结果只反映最终输入；输入过程中 UI 不卡。

#### 任务 B4 · 详情/文件树磁盘 I/O 异步化 【P1 · M5】
- **文件**：MediaLibPage 详情与文件树（1126 `ReadAllText`、1159/1441 `EnumerateFiles`、1526/1591 目录枚举）
- **方案**：正文 `ReadAllTextAsync`；`Directory.EnumerateFiles(AllDirectories)`、逐目录计数放 `Task.Run`，完成后回 UI 线程填充；文件树深层节点**按需展开时**再枚举子层（懒展开），而非一次性递归建满。
- **验收**：打开含大量文件的作品详情/文件树时 UI 不冻结；切换语言/重新可见重建文件树不阻塞。

### 阶段 C —— 下载 / 搜索 / 已下载页

#### 任务 C1 · 下载页每秒刷新降本 【P0 · D1】
- **文件**：[src/Views/DownloadPage.xaml.cs](../src/Views/DownloadPage.xaml.cs) `_refreshTimer`/`Refresh`(163,382-499)
- **现状**：每秒全表 `SELECT download_list` + 重算聚合 + 画刷分配。增量复用已有，但**全表查询本身**是每秒固定成本。
- **方案**（择优组合）：
  1. **进度用内存源**：进度/速度直接读 `DownloadEngine.DownloadProgress`/`UnzipProgress`（`ConcurrentDictionary`），无需查库；DB 只在**结构变化**（新增/删除/状态跃迁）时读，由引擎发事件或置脏标志触发。
  2. 若保留轮询，把 `SELECT` 放 `Task.Run`，UI 线程只做增量 diff；空闲（无活动下载）时降频到 3–5s 或停表。
  3. 画刷 `BrushOf()` 结果 `Freeze()` 并按颜色缓存复用，避免每 tick 分配。
- **验收**：下载页常驻时 CPU/GC 明显下降；进度更新仍每秒平滑；无活动下载时几乎零开销。

#### 任务 C2 · 搜索页社团同步定时器去 N+1 【P0 · S1】
- **文件**：[src/Views/SearchPage.xaml.cs](../src/Views/SearchPage.xaml.cs) `SyncMakerDownloadStates`(633-676)
- **现状**：每秒全表扫 `download_list`，再对每个可见社团作品 `Db.Scalar` 查 `works.state`（N+1）。
- **方案**：把逐项 `Db.Scalar` 合并为**一次批量 `IN` 查询**（参照 `MediaLibraryService.BuildConds` 的 `@id{i}` 参数化 IN 写法）；同 C1，空闲降频/停表；能用引擎内存状态就不查库。
- **验收**：显示 N 个社团作品时每 tick 查询数从 N+1 降到 1–2；参数化不回退为字符串拼接。

#### 任务 C3 · 下载页 / 搜索社团列表虚拟化 【P1 · D2 / S2】
- **文件**：DownloadPage `GroupList`(120)/`Nodes`(193)、SearchPage `MakerList`(134-191)
- **方案**：`GroupList` 与 `MakerList` 改用启用虚拟化的 `ItemsControl`/`ListBox`（`VirtualizingStackPanel` + `Recycling`）；`MakerList` 的 `WrapPanel` 换 `VirtualizingWrapPanel` 或去掉 `CanContentScroll="False"`。文件树 `Nodes` 至少给容器加 `MaxHeight` 内滚动 + 虚拟化（已有 `MaxHeight`，补虚拟化）。
- **验收**：百级社团/大量文件展开时渲染元素数量恒定、滚动顺滑。

#### 任务 C4 · 已下载页搜索/筛选/排序防抖与异步 【P1 · L1】
- **文件**：[src/Views/DownloadedPage.xaml.cs](../src/Views/DownloadedPage.xaml.cs) `Refresh`(113-115)/`SearchBox_TextChanged`(195)
- **现状**：列表已虚拟化（好），但每次搜索/筛选/排序都全表 `SELECT works ORDER BY`。
- **方案**：一次性把 `works` 载入内存 `_all`（本已如此），**搜索/筛选/排序全部在内存 `_all` 上做**，不再回库；仅"刷新按钮"/进入页面时重查。搜索框加 250ms 防抖。
- **验收**：输入/切筛选/点表头排序期间零 DB 查询；仅显式刷新才打库。

#### 任务 C5 · 搜索前入库检查异步 【P2 · S3】
- **文件**：SearchPage(319-320)
- **方案**：把 `SELECT works WHERE work_id=@w` 放入既有的 `await` 搜索流程，不在点击时同步阻塞。
- **验收**：点击搜索后按钮即时响应，不因该查询卡顿。

## 四、约束与风险（务必遵守）

1. **SQL 全程参数化**：新增批量 `IN`、索引、条件拼接一律走 `Db.Select/Execute` 的 `(@name, value)`；Web 端筛选列继续走 `FilterCols` 白名单。（见 CLAUDE.md Gotchas）
2. **下载/解压保持裸线程 + 同步 I/O**：C1/C2 只改"UI 侧读取与刷新"，不得把 `DownloadEngine`/`UnzipService` 的线程模型异步化。
3. **UI 控件只在 Dispatcher 线程访问**：异步解码/查询完成后必须回 UI 线程赋值。
4. **解压/移动进度监视器的 `stop` 判断不可动**（否则进度卡 99% 复活）。
5. **DB 存储值不翻译**：`works.state`（`下载中/已下载/已品悦`）等中文值保持原样，只有显示串走 `I18n.Tr()`。
6. **虚拟化改造注意就地进度更新**：DownloadPage 的 `Children` 按 UUID 扁平列表用于每秒就地更新，虚拟化 `Nodes` 时保留该更新路径（见 CLAUDE.md 对 `RebuildTree`/`Nodes` 的说明）。
7. **每项改造后手动验证**：本项目无测试/无 linter，需 `dotnet run --project src/DLsiteMedia.csproj` 从仓库根实跑（DB 定位依赖工作目录）。

## 五、验收总目标

- 万级 `works` 媒体库：首屏 < 1s，滚动内存平稳、无累积泄漏。
- 下载页 / 搜索页常驻时：无活动任务近乎零开销；有任务时进度每秒平滑更新且不查全表。
- 所有页面搜索/筛选/排序：输入过程零逐字查询、UI 不冻结。
- 任意页面切换：无批量 conf 写入、无 UI 线程阻塞式磁盘/网络 I/O。
